# 个人 Design 规范

版本：3.6.1 · 更新：2026-11-12
适用于 UI 任务；用户明确要求与项目约束优先，不固定业务、技术栈或视觉风格。

局部明确修改只需 [快速入口](DESIGN-CORE.md)；本文件供新页面和设计决策按章节读取。

## 1. 执行范围

- 小组件、表单、文案和样式微调：定位相关代码，复用现有设计，直接实施并局部验证。新页面继承主题和样板页；仅具体设计问题或整体改版按需用 Oil UI Pro。
- 默认深化一个方向；用户要求比较才做多方案。已授权实现不默认增加生图、方案确认或过程文档；仅影响核心方向且无法推断的歧义需要询问。技能及其参考文件不扩大授权、重复索取已有批准或省略项目要求的验证。

## 2. 组件与工具

复用顺序：项目现有组件与样板 → 已安装组件库 → 必要的最小业务组件。先检查相关实现；已有能力满足需求时不另造，不重复包装基础组件，不因单次使用或机械次数阈值提前抽象，不建立第二套组件或主题体系。必要时优先组合、参数或变体；不重写库已提供的弹窗、焦点、键盘、选择、拖拽等行为。同类界面统一布局、间距和响应式行为；同步清理重复样式，避免叠加覆盖。

| 能力 | 使用边界 |
| --- | --- |
| Astryx | 新 React 项目适用时优先；已选用项目的组件、主题与模板基准 |
| shadcn/ui、shadcn-vue | 已有项目继续复用；Vue 或 Astryx 不适用时按需选用成熟方案 |
| Oil UI Pro | 按需改善布局、内容、响应式与视觉细节，保持已确认风格 |
| web-design-guidelines | 按需专项检查，不随每次 UI 修改全面审计 |
| Playwright CLI | 页面、交互与响应式验证，复用预览和浏览器会话 |
| browser-skill | 需要已有登录态时使用，不与其他浏览器工具重复同一流程 |

- 每个项目一套主视觉体系，按需安装并锁定依赖；初始化前检查已有配置，保留用户定制。Astryx 须兼容项目 React 版本；静态前端配独立 API 可用 React + Vite + TypeScript，不为美观引入 Next.js。
- Astryx 新页面先复用项目样板；确无适用样板时才选官方模板，保留主题、排版、间距与比例，按业务、响应式和可访问性调整；局部修改不重搭模板，允许必要的语义 HTML 与 CSS。
- Astryx 用项目版本 CLI，已知组件优先 `component <Name> --props`，多个组件批量查询，缺示例再查完整文档；其他库按全局规则查询，来源充分即停止扩搜。
- 图标沿用项目体系，关键操作与状态适量配文字，不用 Emoji 代替功能图标。动画、拖拽、分栏和状态库按真实需求添加。

## 3. 视觉与体验

- 复用主题变量；缺失时集中定义颜色、字体、间距、尺寸、圆角和状态，不逐处硬编码或套用其他项目数值。
- 标题、核心信息与主操作层级明确；后台重信息和操作效率，商城按内容组织。避免无意义大标题、空白、嵌套卡片和装饰，渐变、阴影与动效服务于内容。
- 保留业务、权限与操作路径；覆盖受影响流程的加载、空数据、错误重试、禁用、提交中和成功反馈，高影响操作有确认与结果反馈。
- 设置、配置和编辑窗口默认使用居中弹窗，不使用侧边抽屉；长内容在窗口内滚动，标题、关闭入口和底部操作区保持可见。
- 用真实中文长标题、数字、日期、金额、缺图与列表数据检查布局；模拟数据标明，不虚构销量、评价或成功结果，不放无关开发说明。
- 窄屏按任务重排，宽表格明确滚动或收起策略；文字可读、触控面积合适、表单有标签、焦点可见、状态不只靠颜色。图标按钮有可访问名称，尊重减少动态效果偏好。
- 控制首屏资源、重复请求、过期数据、昂贵渲染与布局跳动；先测瓶颈再优化，不为跑分换框架或增加复杂依赖。

## 4. 验证与交付

- 局部修改验证影响区域，公共组件抽查受影响页面；新页面、布局或响应式改动覆盖手机与桌面，主要操作从真实入口走到可观察结果。
- 批量查看实际画面的溢出、遮挡、换行、层级和一致性后集中修正，不每改一行就截图。已通过的检查仅在相关代码、环境变化或新疑点出现时重跑。
- 独立评审按任务风险或用户要求使用，不为普通页面自动启动多个评审代理。按风险完成项目要求的类型检查、测试与生产构建，设计技能不得省略；失败先诊断。编译、评分和保存截图不能代替实际查看与交互验收。
- 简述结果、必要证据与未验证范围；未测量不宣称提速百分比，无法运行或看图时明确说明。

## 5. 按需参考与维护

- 方向未定或用户要求参考时读 [设计参考](references/inspiration.md)。
- 涉及加载、请求、资源或渲染性能的问题与改动时读 [性能细则](references/performance.md)，不因纯视觉改版自动加载。
- 项目 DESIGN.md 仅维护当前组件、主题与布局决定，历史另存；无新决定不生成文档，不并行维护竞争的设计系统。
- 个人规范只沉淀已验证的跨项目经验。获授权修改时同步 CHANGELOG.md 与本地副本，说明原因、范围和同步状态；普通项目修改不自动更新个人规范。
