# 项目开发规范

## 一、项目原则
- 遵循项目现有技术栈、架构、编码风格和设计规范。
- 优先简洁、高性能、低资源占用和长期可维护性。
- 保持模块职责清晰，避免过度设计和无关功能。
- 涉及 UI、UX、交互或前端视觉优化时，按需读取个人设计规范 `https://github.com/Avlonjune7/Design/blob/main/DESIGN.md`；优先遵循项目已有设计约束，非相关任务不加载。

## 二、开发流程
- 遵循全局工作流：需求 → 规划 → 开发 → 测试 → 审查 → 交付。
- 开发前按需查阅 `docs/PRD.md`、`docs/ARCHITECTURE.md`、`docs/PLAN.md`。
- 复杂任务先拆解，按依赖顺序实施，逐项完成业务闭环。
- 前后端使用真实接口，不以 Mock 或硬编码冒充正式功能。
- 数据库、API 和公共协议变更须考虑兼容性、迁移及回滚。

## 三、开发环境与会话复用
- 开发环境属于项目而非单次 AI 会话；新会话优先复用已有工作区、依赖、服务、容器与预览环境。
- 开发前按需查看 `docs/ENVIRONMENT.md`，核实实际进程、端口、服务健康状态及预览地址；确认可用则直接复用，不因切换会话重新搭建。
- 不重复安装未变更的依赖、初始化数据库、创建沙盒或启动已有服务；环境异常先诊断与恢复，确需重建时才按项目现有流程操作。
- 多会话可能共享工作区和服务；未经确认不得终止共享进程、删除容器、重置数据或覆盖其他会话的修改。
- 区分本地共享环境和独立隔离沙盒；无法共享时优先使用已有持久化环境或标准启动流程，不假定进程可以跨沙盒复用。
- `docs/ENVIRONMENT.md` 按需记录工作区、启动命令、端口、预览地址及恢复方法，不保存凭据或易过期的运行状态；实际情况以现场检测为准。
- 优先复用现有检查、启动脚本，不为环境复用额外引入复杂工具或常驻服务。

## 四、测试与验收
- 根据改动范围执行相关测试、静态检查和构建验证。
- 关键业务变更增加集成测试、安全检查和回归验证。
- 重点检查功能完整性、错误处理、性能及兼容性。
- 未通过必要验证的任务不得标记为完成。

## 五、项目文档
- `README.md`：项目介绍、运行和部署说明。
- `docs/PRD.md`：需求、功能范围与验收标准。
- `docs/ARCHITECTURE.md`：技术架构和模块职责。
- `docs/PLAN.md`：任务拆解、实施进度及状态。
- `docs/ENVIRONMENT.md`：开发环境、服务端口、预览地址及恢复方法（按需建立）。

文档按需维护，保持与实际代码一致，避免重复和过时内容。
