# 项目开发规范

继承全局工作约定；接入项目时补充实际技术栈、运行、验证与部署命令及适用范围，优先引用现有脚本。

- 沿用现有架构、组件和编码风格；现有组件或已安装库满足需求时不重复实现，仅能力不足时补最小业务组件，避免无关改动与提前抽象。
- 按任务读取已有文档，明确需求、影响范围和验收标准；不为开始工作补建整套文档。
- UI 遵循个人设计规范；项目 DESIGN.md 只记录当前组件、主题与布局选择，历史决定另存。
- 正式功能接真实接口，示例与 Mock 明确标识；覆盖权限、错误及关键业务状态。数据库、API 与协议变更考虑兼容、迁移和回滚。
- 首次使用或相关变化时核实现有环境、服务与预览，其余复用；保护共享进程和数据，不假定不同环境互通。
- 按影响范围完成测试、静态检查与构建；关键业务补充必要回归验证，未通过不得标记完成。
- 文档按需随变更维护，记录运行部署与稳定环境信息，不存凭据、临时状态或重复规则。
