# 项目开发规范

继承全局工作约定，以下仅补充项目要求。

- 沿用现有技术栈、架构和编码风格；保持模块职责清晰，优先性能、低资源占用与可维护性，避免无关功能和过度设计。
- 按任务读取已有的 `docs/PRD.md`、`docs/ARCHITECTURE.md`、`docs/PLAN.md`，明确需求、影响范围与验收标准，不要求补齐文档才能开始。
- UI 任务只补充读取相关项目设计约束；任务分级与通用设计规则沿用全局约定，非 UI 任务不加载设计规范。
- 在项目 DESIGN.md 明确当前组件体系、主题与布局；选用 Astryx 时沿用其视觉基准，Oil UI Pro 仅按需完善体验。CLI 初始化不得覆盖已有工程规则，历史设计决定与当前规则分开记录。
- 正式功能使用真实接口；示例与 Mock 明确标识，不冒充业务闭环；覆盖错误处理、权限及关键业务状态。
- 数据库、API 和公共协议变更考虑兼容性、迁移及回滚。
- 复用现有工作区、依赖、容器、服务与预览；按需读取 `docs/ENVIRONMENT.md` 并核实现状，保护共享进程与数据，不假定不同执行环境可共享。
- 按影响范围执行测试、静态检查和构建；关键业务变更补充集成、安全与回归验证，必要验证未通过不得标记完成。
- 文档随实际变更维护：README 记录运行部署，PRD 记录需求验收，ARCHITECTURE 记录架构，PLAN 记录进度；ENVIRONMENT 按需记录稳定的启动、端口与恢复方式，不存凭据、临时状态或重复说明。
