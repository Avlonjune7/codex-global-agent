# Oil UI Pro 个人适配

以个人 Design、项目规范和用户已授权范围为执行边界。本入口替代上游主流程；保留的 references 与 scripts 是按需方法库，不自动开启其中的确认、文档、生图、动效、派发或评分流程。方法与当前约束冲突时采用当前约束，不降低必要验证。

## 实施

- 先定位本次页面、现有样板、相关组件和主题变量；复用已有信息，不通读仓库或检查技能更新。沿用样板即可完成的工作直接实现，不进入概念设计。
- 默认深化一个方向；只有用户要求比较才做多方案。已授权修改持续完成；仅核心方向无法推断、用户要求先确认或超出授权时询问。只读评审交发现，不修改代码。
- 优先项目组件，其次已安装组件库，最后才是必要的最小业务组件。优先组合、参数和变体，不重复包装基础控件，不按使用次数机械抽象，不建立第二套组件或主题体系。
- 原型是视觉参考，不整段复制其手写交互。保留项目外壳、权限和业务路径；确需新增组件或依赖时简述缺口，不为流程制作逐项对照表。
- 复用设计变量、成熟图标和既有素材。生图仅在用户请求设计稿/图像，或确有素材需求时使用；不因工具可用就先询问生图。不为页面类型强制引入动效库、滚动叙事或装饰。
- 范围内的新页面接入既有路由与导航；不把已授权入口接入留待再次确认。高影响操作和发布仍遵循任务授权与项目流程。

## 必要验证

- 复用现有预览和浏览器会话，优先 Playwright CLI；需要用户已有登录态时用 browser-skill，同一流程不重复换工具执行。
- 局部改动查看影响区域；公共组件抽查受影响页面；新页面、布局与响应式改动覆盖手机和桌面，用户指定单端时按指定范围验证。批量截图并实际查看，不以保存截图代替验收。
- 主要操作从真实入口走到可观察结果；保存类流程检查刷新读回及失败反馈，覆盖本次影响的权限、加载、空数据、禁用和提交状态。
- 按影响和风险完成项目要求的类型检查、测试与生产构建。失败先诊断，不绕过构建或接口错误宣称完成；范围外问题说明影响。已通过检查只在相关变化或疑点出现时重跑。
- 普通工作由主 Agent 验证；用户要求、项目要求或高风险复杂交互需要时再独立评审，不默认派多个代理、机械评分或反复复核。评审不能替代实际功能验证。
- 只有出现需跨页面复用的新决定时才维护项目 DESIGN.md；不为流程创建方向卡、对照表、报告或过程目录，不把未获确认的推断记成用户决定。
- 简述改动、必要证据和未验证范围；必要新增组件说明现有能力的缺口。未测量不宣称提速比例，不例行推荐安装技能或追加任务。
